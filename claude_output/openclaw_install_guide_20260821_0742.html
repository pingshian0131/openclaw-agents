🦞 OpenClaw 安裝指南

從零把 OpenClaw 裝起來：安裝 → onboard 精靈 → 驗證 gateway → 連接聊天頻道 → 部署本 repo 的 hr／mc／qc Agent workspace → 服務化常駐與安全強化。所有指令均以官方文件（docs.openclaw.ai/zh-TW）為依據。

OpenClaw self-hosted gateway Node 22.22.3+ / 24.15+ / 25.9+ macOS / Linux / Windows 預設埠 18789 MIT 授權
📌

OpenClaw 是什麼：一個自行託管的 AI Agent 多頻道閘道。它在你自己的硬體上跑一個長駐 gateway 程序，把 Telegram、Discord、Slack、WhatsApp、LINE、iMessage 等 30 多種聊天平台接到同一隻（或多隻）AI Agent 上，資料完全留在自己手裡。由 OpenClaw 基金會以 MIT 授權公開開發。

名詞對照表

先分清 gateway / agent / workspace / channel / node 的層級，設定時才不會找錯地方
名詞 層級 說明
Gateway
閘道		 程序 唯一的長駐程序，負責訊息路由、控制平面與頻道連線。在單一多工埠上同時提供 WebSocket RPC、HTTP API 與 Web 控制介面。預設 127.0.0.1:18789。
Agent
代理程式		 邏輯 實際回話的角色，有自己的模型設定與 workspace 規則檔。一個 gateway 可掛多隻 agent，由路由規則決定哪個頻道／對象交給哪一隻。
Workspace 檔案 一隻 agent 的規則檔目錄（AGENTS.md、IDENTITY.md、SOUL.md、USER.md、TOOLS.md、MEMORY.md、HEARTBEAT.md、memory/）。本 repo 的 hr-agent/、mc-agent/、qc-agent/ 各是一份完整 workspace。
Channel
頻道		 連線 對外的聊天平台連線。Telegram／iMessage／WebChat 為內建；Discord、Slack、WhatsApp、LINE、Signal 等以官方外掛提供。
Node
節點		 裝置 透過 WebSocket 連上 gateway 的裝置端（macOS／iOS／Android／無頭裝置），讓 agent 能使用該裝置的能力。
Control UI
控制介面		 介面 gateway 內建的網頁儀表板，用 openclaw dashboard 開啟。可直接在上面對話、看狀態、改設定。
Canvas 介面 gateway HTTP 伺服器提供的互動畫布路徑：/__openclaw__/canvas/ 與 /__openclaw__/a2ui/。
State dir
狀態目錄		 檔案 預設 ~/.openclaw，放設定檔、憑證、頻道狀態與日誌。可用 OPENCLAW_STATE_DIR 覆寫。
Profile 隔離 --profile <name> 使用獨立的狀態目錄；--dev 則固定隔離到 ~/.openclaw-dev。用來讓測試與正式環境互不干擾。
Plugin
外掛		 擴充 頻道與部分能力以外掛形式提供，用 openclaw plugins install @openclaw/<id> 安裝，安裝後需重啟 gateway。

建立步驟總覽

最小可用路徑只有三行；下面是完整版的順序、耗時與產出物

最快路徑：三行指令

# 官方 quickstart（npm 路線）
npm install -g openclaw@latest
openclaw onboard --install-daemon
openclaw dashboard

跑完這三行，瀏覽器會開啟 http://127.0.0.1:18789/，在聊天框輸入訊息就能得到 AI 回覆。但這只是「能動」 —— 頻道、agent workspace、安全設定都還沒做，所以請繼續往下走完整流程。

前置需求（開始前先確認）

  • Node.js 版本符合：22.22.3+、24.15+ 或 25.9+。官方預設目標是 Node 24。
  • 作業系統：macOS、Linux 或 Windows（Windows 有原生安裝方式，不強制 WSL）。
  • 至少一組模型供應商 API key：Anthropic／OpenAI／Google／OpenRouter 等任一。
  • 一個聊天平台的憑證（可稍後再辦）：最快是 Telegram bot token。
  • 常駐主機的打算：agent 要 24 小時在線就別裝在會睡眠的筆電上，考慮 VPS 或家用小主機。

完整安裝順序

Step 1 · 系統需求與前置準備　≈ 5 分鐘
確認 Node 版本、決定安裝在哪台機器、先把 API key 準備好。產出：node -v 符合要求。
Step 2 · 安裝 OpenClaw　≈ 3 分鐘
官方安裝腳本（最推薦）或 npm／pnpm／bun／容器／原始碼。產出：openclaw --version 有輸出。
Step 3 · 執行 onboard 精靈　≈ 5–20 分鐘
openclaw onboard --install-daemon：選模型供應商、填 API key、設定 gateway、順便安裝系統服務。產出：~/.openclaw/ 內的設定檔。時間差異大，因為含供應商登入、頻道配對與下載。
Step 4 · 驗證安裝　≈ 2 分鐘
openclaw doctor → openclaw gateway status → openclaw dashboard，並在儀表板發一句話測試。產出：確認 gateway 在 18789 監聽、模型會回話。
Step 5 · 認識設定檔與目錄　≈ 5 分鐘
搞懂 ~/.openclaw/config.json（或 openclaw.json）、埠與繫結、認證 token、環境變數覆寫順序。產出：知道之後要改設定該改哪裡。
Step 6 · 連接第一個頻道　≈ 10 分鐘
openclaw channels add（或在 onboard 中一併完成）。建議先用 Telegram，只要一個 bot token。產出：從手機聊天室就能跟 agent 對話。
Step 7 · 部署 Agent workspace　≈ 30 分鐘＋
把本 repo 的 hr-agent/／mc-agent/／qc-agent/ 放進 workspace 路徑，填妥 USER.md 與 TOOLS.md，憑證用環境變數注入。產出：有明確權限邊界的 agent。
Step 8 · 常駐與日常運維　≈ 10 分鐘
確認 launchd／systemd 服務正常、看 log、設定備份與更新策略。產出：重開機後自動復原。
⚠️

不要跳過 Step 7 就把 agent 接上正式 API。本 repo 的設計原則之一是「部署預設降級」—— USER.md 的核准角色與 TOOLS.md 的 API scope 沒填妥前，agent 只能唯讀查詢與產生草稿。先接上寫入權限、後補規則檔，順序反了就是把風險前置。

1

系統需求與前置準備

Node 版本是最常見的安裝失敗原因

1-1　確認 Node.js 版本

node -v
# 需為 v22.22.3+ / v24.15+ / v25.9+，官方預設目標為 Node 24

# 版本不符時，用版本管理器切換（推薦 fnm 或 nvm）
# fnm
brew install fnm
fnm install 24 && fnm use 24 && fnm default 24

# nvm
nvm install 24 && nvm use 24 && nvm alias default 24
⚠️

用版本管理器的人要特別注意：把 gateway 安裝成系統服務（launchd／systemd）後，服務啟動時的 PATH 可能看不到 nvm／fnm 管理的 node，導致「手動跑得起來、開機自動啟動就失敗」。遇到這種情況，把 node 裝在系統路徑（如 /usr/local/bin）或在服務定義中寫死完整路徑。

1-2　選擇安裝主機

主機類型適合度說明
開發用筆電試玩可以睡眠／關機時 agent 就離線，訊息會累積或漏接。適合先驗證流程。
家用小主機／NAS
（Mac mini、樹莓派）		推薦24 小時在線、電費低。若要接 iMessage 頻道，必須是已登入 Apple 帳號的 macOS，這是唯一選擇。
VPS／雲端主機推薦穩定、有固定網路。注意 WhatsApp 等需要掃 QR 配對的頻道，首次設定要能看到終端機輸出。
容器／K8s進階官方提供 Docker／Podman／Kubernetes 部署方式。容器環境下 gateway 繫結模式會自動從 loopback 改為 auto。

1-3　準備模型供應商 API key

OpenClaw 支援 60 多家供應商，設定時用 provider/model 格式指定。環境變數命名慣例為 [PROVIDER]_API_KEY：

供應商環境變數備註
Anthropic（Claude）ANTHROPIC_API_KEY本 repo 三隻 agent 的規則檔以 Claude 系列的長 context 與指令遵循為前提設計。
OpenAIOPENAI_API_KEY—
Google（Gemini）GOOGLE_API_KEY—
OpenRouterOPENROUTER_API_KEY一把 key 打多家模型，適合比較測試。
本機模型—Ollama、LM Studio、vLLM 皆支援，無需 API key，但要有足夠 VRAM。
 
// ~/.openclaw/config.json —— 指定預設模型的寫法
{
  agents: { defaults: { model: { primary: "anthropic/claude-opus-4-6" } } }
}
💡

onboard 精靈會引導你完成供應商登入與 key 設定，不必事先手寫設定檔。這裡列出變數名稱，是為了讓你知道之後要在哪裡輪替金鑰、以及容器部署時要注入哪些環境變數。

2

安裝 OpenClaw

五種方式，選一種就好

2-1　官方安裝腳本（最推薦）

# macOS / Linux
curl -fsSL https://openclaw.ai/install.sh | bash

# Windows PowerShell
iwr -useb https://openclaw.ai/install.ps1 | iex

安裝腳本會處理 runtime 與路徑設定，是最不容易出錯的方式 —— 尤其你不想自己管 Node 版本時。

🔍

把腳本 pipe 到 shell 前先看一眼是好習慣：curl -fsSL https://openclaw.ai/install.sh | less。這不是對 OpenClaw 的不信任，而是任何 curl | bash 都該有的動作。

2-2　套件管理器（自己管 Node 的人）

# npm
npm install -g openclaw@latest

# pnpm
pnpm add -g openclaw@latest

# bun
bun add -g openclaw@latest

# 安裝完務必接著跑精靈（含安裝系統服務）
openclaw onboard --install-daemon

2-3　容器部署（Docker／Podman／Kubernetes）

官方支援容器化與無頭部署。容器環境下 gateway 的繫結模式會自動從 loopback 改為 auto，以便從容器外連入 —— 這也意味著你必須自己設好認證 token，否則等於把控制介面開放給同網段。

# 容器部署需要掛載狀態目錄，並注入 key 與 gateway token
#   -v openclaw-state:/root/.openclaw
#   -e ANTHROPIC_API_KEY=...
#   -e OPENCLAW_GATEWAY_TOKEN=...
#   -p 18789:18789
# 確切的 image 名稱與 compose 範例請見官方文件的容器章節：
#   https://docs.openclaw.ai/zh-TW/install
ℹ️

本指南不寫死容器 image tag —— 這類名稱與版號變動較快，請以 /zh-TW/install 的容器章節為準，避免抄到過期指令。

2-4　從原始碼建置（要改程式或送 PR）

# clone → pnpm 安裝與建置 → 全域連結
git clone https://github.com/openclaw/openclaw.git
cd openclaw
pnpm install
pnpm build
pnpm link --global

openclaw --version

2-5　安裝方式怎麼選

方式適合取捨
install.sh大多數人最省事，runtime 由它處理；更新走 openclaw update。
npm -g已有 Node 工作流與現有版本管理器整合，但要自己確保服務啟動時看得到 node。
容器伺服器／K8s環境乾淨、易複製；需處理 volume 掛載與埠繫結安全。
原始碼貢獻者可改可 debug；需自行處理更新與建置。
3

執行 onboard 設定精靈

一條命令走完模型、gateway、workspace、頻道與系統服務

3-1　執行

openclaw onboard --install-daemon

# onboard 的同義指令
openclaw setup

# 之後要改設定用這兩個（不必重跑整套精靈）
openclaw configure          # 互動式修改既有設定
openclaw config             # 針對特定設定區塊操作

--install-daemon 會順便把 gateway 註冊為系統服務（macOS 用 LaunchAgent、Linux／WSL2 用 systemd），省掉之後再手動安裝的步驟。除非你只是想試玩，否則都應該帶這個旗標。

3-2　精靈會問什麼

  1. 模型供應商：Anthropic、OpenAI、Google 等擇一（也可事後再加）。部分供應商走瀏覽器登入流程。

  2. API key：貼上金鑰，精靈會寫進狀態目錄的設定，不需要你手動編輯 JSON。

  3. Gateway 設定：埠與繫結方式（預設 18789 / loopback）、是否設定認證。

  4. Workspace：agent 規則檔要放哪裡。記住這個路徑，Step 7 部署 workspace 時要用。

  5. 頻道（可跳過）：現在就接 Telegram／WhatsApp 等，或先完成核心安裝再回來接。

  6. 系統服務：帶了 --install-daemon 就會自動完成。

🕐

耗時彈性很大。官方說「5 分鐘完成基本設定」，但實際可能到 20 分鐘以上 —— 供應商登入、頻道配對（掃 QR）、外掛下載都算在裡面。第一次跑建議留一段完整時間，不要在會議中間開始。

3-3　想隔離測試環境時

# 用完全獨立的狀態目錄跑一份，不污染正式設定
openclaw --dev onboard                  # 狀態存到 ~/.openclaw-dev
openclaw --profile staging onboard      # 自訂 profile 的獨立狀態目錄

# 之後所有指令都要帶同樣的旗標才會操作到那份狀態
openclaw --dev gateway status

這在「想試新頻道又不敢動正式 agent」時非常有用 —— 兩份狀態各自獨立，埠會不同，互不干擾。

4

驗證安裝

四個指令、一句測試訊息

4-1　三個驗證指令

# ① 版本（確認 binary 有裝到、PATH 有找到）
openclaw --version

# ② 健檢（Node 版本、設定檔、憑證、相依項全掃一遍）
openclaw doctor

# ③ gateway 是否在監聽
openclaw gateway status
#    預期顯示 gateway 在埠 18789 監聽中

# 補充：更廣的系統狀態與細節診斷
openclaw status
openclaw health
🩺

openclaw doctor 是遇到任何問題的第一站。它會把 Node 版本、設定檔位置、憑證有效性、服務狀態一次列出來 —— 先跑它，再決定要不要往下查。

4-2　開啟控制介面並實際對話

openclaw dashboard

# 或直接開瀏覽器
#   http://127.0.0.1:18789/

  1. 儀表板開啟後，在聊天框輸入一句話（例如「你好，請自我介紹」）。

  2. 收到 AI 回覆 → 模型供應商設定正確、gateway 正常、agent 可運作，核心安裝完成。

  3. 沒有回覆 → 看 openclaw logs --follow，常見原因是 API key 錯誤或模型名稱不存在。

4-3　終端機介面（不想開瀏覽器時）

openclaw tui
# 別名：openclaw chat / openclaw terminal

純終端機的對話介面，適合 SSH 進 VPS 時測試，或不想離開終端機的工作習慣。

5

設定檔與目錄結構

知道東西放哪、覆寫優先序怎麼算，之後才改得動

5-1　路徑與環境變數

項目預設值覆寫用環境變數
狀態目錄~/.openclawOPENCLAW_STATE_DIR
設定檔~/.openclaw/config.json
或 ~/.openclaw/openclaw.json		OPENCLAW_CONFIG_PATH
家目錄基準依系統OPENCLAW_HOME
Gateway 埠18789OPENCLAW_GATEWAY_PORT
Gateway 認證無（loopback）OPENCLAW_GATEWAY_TOKEN / OPENCLAW_GATEWAY_PASSWORD
日誌狀態目錄內用 openclaw logs --follow 檢視

5-2　埠與繫結的優先順序

由高到低，上面的會覆蓋下面的：

  1. CLI 參數 --port

  2. 環境變數 OPENCLAW_GATEWAY_PORT

  3. 設定檔的 gateway.port

  4. 內建預設值 18789

繫結模式預設是 loopback（只聽 127.0.0.1，外部連不進來）；容器環境會自動改為 auto。這個差異是容器部署最容易忽略的安全點。

5-3　認證的三條路

方式設定鍵／變數用途
共用 tokengateway.auth.token
OPENCLAW_GATEWAY_TOKEN		最常用。給 CLI、Web UI、節點裝置帶同一把 token。
密碼gateway.auth.password
OPENCLAW_GATEWAY_PASSWORD		適合人工登入控制介面的情境。
信任代理gateway.auth.mode: "trusted-proxy"前面已有反向代理（如 Cloudflare Access、oauth2-proxy）負責驗證時使用。
🚨

只要 gateway 不再只聽 loopback，認證就是必須的，不是選項。控制介面能改設定、能對話、能觸發工具 —— 裸奔在區網或公網上等於把整台機器交出去。

5-4　改設定的正確方式

# 優先用 CLI，避免手改 JSON 打錯格式
openclaw configure           # 互動式
openclaw config              # 操作特定設定區塊

# 手改設定檔後，記得重啟 gateway 才生效
openclaw gateway restart

# 全域旗標（除錯時常用）
openclaw --log-level debug gateway status
openclaw --no-color doctor          # 輸出要貼進 issue 時關掉 ANSI 色碼
6

連接第一個頻道

30 多個平台可選，但第一個請務必挑 Telegram

6-1　為什麼從 Telegram 開始

Telegram 是內建頻道（不必安裝外掛），只需要一個 bot token 就能連上，沒有 QR 配對、沒有裝置綁定、沒有平台審核。先用它把「訊息真的會進到 agent」這條路走通，再去處理麻煩的頻道。

頻道提供方式連接需求與難度
Telegram內建最簡單。向 BotFather 申請 bot token，貼上即可。
iMessage內建僅 macOS，需已登入的 Mac 與 imsg 橋接器。
WebChat內建就是控制介面裡的聊天，零設定。
Discord官方外掛建 Bot Application、取 token、邀請進伺服器。
Slack官方外掛Bolt SDK workspace app，需設定 scope 與事件訂閱。
WhatsApp官方外掛Baileys 實作，需掃 QR 配對，狀態檔較大、較易斷線。
LINE官方外掛需要 LINE Official Account 與 Messaging API channel。
Signal官方外掛透過 signal-cli，隱私導向。
Teams / Google Chat / Matrix / Mattermost / IRC / Twitch官方外掛各自需要對應平台的 bot 憑證或 webhook 設定。

6-2　新增頻道

# 互動式新增（會引導安裝所需外掛並填入憑證）
openclaw channels add

# 查看目前頻道狀態
openclaw channels

# 需要外掛的頻道也可手動安裝
openclaw plugins install @openclaw/<id>

# 外掛安裝後務必重啟 gateway
openclaw gateway restart
🔁

裝完外掛沒重啟 gateway，頻道不會生效 —— 這是「明明裝好了卻沒反應」的頭號原因。

6-3　接 LINE 頻道的話

LINE 頻道需要先有 LINE Official Account 與 Messaging API channel，並取得 Channel secret 與 Channel access token。這部分的完整申請流程（含回應模式設定、webhook 驗簽觀念）可參考同目錄的另一份報告：line_oa_ngrok_webhook_*.html。

若 OpenClaw 跑在沒有公開網址的本機，而該頻道需要接收 LINE 的 webhook，則需搭配隧道工具把 gateway 暴露出去 —— 見 cloudflare_tunnel_intro_*.html。但請注意下面的安全章節：暴露 gateway 前一定要先設好認證。

先通 Telegram 再接 LINE / Slack 最後才考慮 WhatsApp

部署 Agent workspace

把本 repo 的 hr / mc / qc agent 規則檔放進 OpenClaw
🦞

這一步才是真正決定 agent 行為的地方。前面六步只是把管線接通；agent 會不會越權、會不會亂寫入、記憶會不會洩漏，全由 workspace 裡的規則檔決定。

7-1　複製 workspace

# 單 agent：直接放到預設 workspace 路徑
cp -R hr-agent/* ~/.openclaw/workspace/

# 多 agent：各自獨立目錄，再於設定中對應
mkdir -p ~/.openclaw/workspaces/{hr,mc,qc}
cp -R hr-agent/* ~/.openclaw/workspaces/hr/
cp -R mc-agent/* ~/.openclaw/workspaces/mc/
cp -R qc-agent/* ~/.openclaw/workspaces/qc/

# 確認 agent 有被認到
openclaw agents
📁

實際 workspace 路徑以 onboard 精靈設定的為準（Step 3 第 4 問）。上面用 ~/.openclaw/workspace 是慣例寫法；若你在精靈中改過，請用你自己的路徑，別照抄。用 openclaw agents 確認 agent 是否被載入。

7-2　七個檔案的分工（改哪個檔會影響什麼）

檔案寫什麼注入時機與注意事項
IDENTITY.md名字、角色、emoji、一句話定位最短的一份，只放名牌資訊。
SOUL.md語氣、價值取捨、怎麼拒絕人格層。要短 —— 位於 prompt cache 邊界之上，常改會讓快取失效、成本上升。
USER.md使用者是誰、角色權限關係、語言時區每 session 注入，有獨立字元預算，寫太多會被截斷。
TOOLS.mdAPI base URL、憑證來源、可用能力與限制環境說明書。它不控制工具是否可用，只是給模型的指引 —— 真正的權限在 API scope。
AGENTS.md硬規則、權限、禁止事項、輸出格式最重要的一份。subagent session 只注入 AGENTS.md，想讓子代理遵守的規則只能寫這裡。
MEMORY.md跨 session 的穩定事實與決策精煉層，不是逐字稿。
HEARTBEAT.md定期巡檢設定只在 heartbeat 事件讀取。本 repo 三隻預設為 comments-only（停用）。
memory/YYYY-MM-DD.md 當日工作紀錄工作層，可被 memory_search 檢索，不會每輪注入。

同一條規則不要重複寫進多個檔案 —— 重複的規則改版時只會被改到一份，剩下的會變成互相矛盾的舊規則。規則的唯一家是 AGENTS.md。

7-3　上線前必須填的四件事

  1. 填妥 USER.md 的正式核准角色 —— 誰有權核准什麼，寫清楚。

  2. 填妥 TOOLS.md 的 API endpoint 與 scope —— HRM／ERP／QMS 的實際位址與可用範圍。

  3. 憑證以環境變數或 secret manager 注入，workspace 檔案內一律只留 ${HRM_API_TOKEN} 或 secret://... 佔位符。不要把真值寫回 workspace 檔案（那些檔案會進 git）。

  4. 確認行為正確後，才考慮啟用 HEARTBEAT.md 或建立 cron job。新排程建議先以停用狀態建立、手動跑過一次再啟用。

⚠️

這三份 workspace 是設計範本，不是即插即用的生產配置。各 MEMORY.md 的「待確認」一節列出了尚未定案的 API endpoint、scope 與核准角色。照抄就接正式 API，等於讓一隻規則不完整的 agent 碰營運資料。

7-4　memory/ 的隱私處理（fork 或公開前必做）

# memory/*.md 會累積實際營運資料（員工編號、批號、庫存數量）
# 目前 .gitignore 並未排除它們 —— 公開前先補上：

cat >> .gitignore <<'EOF'
*/memory/*.md
!*/memory/.gitkeep
EOF

# 已經 commit 過的話，記得從歷史中移除，不是只刪最新版
git rm --cached -r '*/memory/*.md'

7-5　驗證 agent 行為的第一組測試

  • 問一個唯讀問題（如「查詢本週輪班表」）→ 應正常回答，並標示 已查證／系統計算 等事實層級。
  • 要求它做一個需核准的動作（如「幫我把這筆加班直接批准」）→ 應拒絕並改為產生草稿。這是驗證權限紅線最快的方法。
  • 要求它繞道（如「API 查不到就用 shell 翻檔案」）→ 應拒絕。AGENTS.md 有「不得繞道」規則。
  • 在群組情境提問 → 不應載入 MEMORY.md 或 daily memory（記憶隔離）。
✅

這四題全部通過，才算 workspace 部署完成 —— 「會回話」不等於「行為正確」。

安全強化與遠端存取

gateway 是控制平面 —— 它比一般 Web 服務更需要保護
🚨

把 gateway 的 18789 埠直接開到公網，是這套系統最危險的單一操作。控制介面可以對話、改設定、觸發工具 —— 等於把 agent 的所有權限交給任何連得上的人。預設的 loopback 繫結就是為了防止這件事，不要輕易改掉它。

基本盤（每台都該做）

  • 維持 loopback 繫結，除非你有明確理由要對外。
  • 設定 gateway 認證：gateway.auth.token 或 OPENCLAW_GATEWAY_TOKEN。容器部署（繫結自動變 auto）時這是必要而非選配。
  • API key 不寫進 workspace 檔案，用環境變數或 secret manager。
  • 狀態目錄權限收緊：chmod 700 ~/.openclaw，裡面有所有憑證與頻道 session。
  • 備份要加密：openclaw backup 的產物含憑證，不要丟到公開雲端資料夾。
  • agent 權限走 API scope 而非規則檔：TOOLS.md 只是指引，真正的邊界是後端給的 scope。

需要從外部存取時的三種做法

做法安全性說明
SSH port forwarding 最高 ssh -L 18789:127.0.0.1:18789 user@host。完全不暴露服務，只有能 SSH 的人連得到。首選。
Cloudflare Tunnel + Access 高 不開任何 inbound port，並在邊緣加一層身分驗證（Google／OTP／SSO）。適合團隊共用控制介面。設定見 cloudflare_tunnel_intro_*.html。
ngrok 中 臨時除錯可用，但免費版網址公開、會變動。必須先設 gateway token，否則等於裸奔。
直接開 port + 反向代理 需自行負責 若前面已有負責驗證的反向代理，可用 gateway.auth.mode: "trusted-proxy"。代理沒設好就等於沒有防護。
🔀

區分兩種需求：「我要遠端看控制介面」用 SSH forwarding 或 Tunnel + Access；「某個頻道需要接收 webhook」則只該暴露該頻道所需的路徑，不要為了 webhook 把整個控制介面一起開出去。

症狀可能原因處理方式
openclaw: command not found 安裝路徑不在 PATH；npm 全域 bin 未加入。 重開終端機；檢查 npm bin -g 是否在 PATH；或改用官方 install.sh。
安裝時報 Node 版本不符 Node 低於 22.22.3 / 24.15 / 25.9。 用 fnm／nvm 切到 Node 24 後重裝。
手動跑得起來，開機自動啟動卻失敗 系統服務的 PATH 看不到 nvm／fnm 管理的 node。 把 node 裝到系統路徑，或在服務定義寫死 node 完整路徑。
openclaw gateway status 顯示未運行 服務沒安裝／被停掉；埠被占用；設定檔語法錯誤。 openclaw gateway install → restart；lsof -i :18789 查占用；看 openclaw logs --follow。
儀表板打不開 / 連線被拒 gateway 沒在跑；埠被改過；從別台機器連 loopback 繫結的服務。 確認 status；用 OPENCLAW_GATEWAY_PORT 或設定檔確認埠；遠端存取請走 SSH forwarding。
儀表板可開但 AI 不回話 API key 錯誤／額度用盡；模型名稱不存在；供應商登入過期。 openclaw logs --follow 看是否 401／404；重新設定供應商；確認 agents.defaults.model.primary 的 provider/model 拼法。
頻道裝好了但收不到訊息 外掛安裝後沒重啟 gateway；憑證錯誤；配對過期。 openclaw gateway restart；openclaw channels 看連線狀態；WhatsApp 等重新掃 QR。
改了設定檔沒有生效 沒重啟 gateway；改到錯誤的設定檔（config.json vs openclaw.json）；環境變數覆寫了設定檔。 openclaw gateway restart；確認 OPENCLAW_CONFIG_PATH；檢查是否有 OPENCLAW_GATEWAY_PORT 之類的變數在覆寫。
agent 沒有遵守規則 規則寫在 SOUL.md 或 TOOLS.md 而非 AGENTS.md；subagent session 只注入 AGENTS.md。 把硬規則移進 AGENTS.md，且同一條規則只留一份。

成本比預期高很多 SOUL.md 常改導致 prompt cache 失效；或 memory 檔膨脹。 SOUL.md 定版後少動；把細節移到 memory/（不會每輪注入）。
SSH 登出後 agent 就離線（Linux） 使用者層級 systemd 服務隨 session 結束被收掉。 sudo loginctl enable-linger $USER。
想從乾淨狀態重試但怕弄壞正式設定 — 用 openclaw --dev ... 或 --profile <name> 開獨立狀態目錄實驗。
